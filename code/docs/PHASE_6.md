# Phase 6: local inspection application

Implemented in `inspection/`, `web/`, and the three inspection scripts. Python
FastAPI serves a built React/Vite interface on loopback. SQLite stores
the catalog; PNGs, probability arrays, and immutable snapshots stay in a separate
workspace. Frontend source setup requires Node.js 22.12+ and `npm ci` / `npm run
build` in `web/`. The launcher rebuilds changed source when dependencies are
installed; an existing production build needs only the Python service. No hosted
account is required. See `web/README.md` for frontend development.

## Start

From the project root, double-click `Start_CrackLab.cmd`, or run:

```powershell
.\.venv\Scripts\python.exe scripts/run_inspection.py
```

Open **http://127.0.0.1:8765**. Keep the terminal open. Press Ctrl+C to stop serving.
The launcher imports 32 references from the locally verified Phase 3, 4, and 5
archives. The Phase 5 archive is optional; the two static references are required.
Re-running the launcher checks the archive and model hashes without replacing
existing models or projects. Checkpoint loading is limited to those hash-pinned
local backups and snapshots generated by this application; the browser cannot
upload executable checkpoints or choose arbitrary filesystem paths.

If dependencies are missing:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-app.txt
```

`requirements-app.lock.txt` records the complete tested Windows environment,
including optional browser QA tools. `output/phase6/environment.json` records
runtime versions. The original Kaggle training environment remains a separate
environment; this local application does not assert exact cross-version replay
of the original research experiment.

An alternate workspace/port can be selected from the terminal:

```powershell
.\.venv\Scripts\python.exe scripts/run_inspection.py --port 8766 --workspace artifacts/phase6/another-project-store
```

## Use

1. Keep the initial Road inspection project or create another with the sidebar `+`.
2. Add PNG/JPEG images. Limits are 20 MB, 16 megapixels, and at least 8 pixels per
   side. Decoded contents, not the filename extension, determine acceptance.
   Exact pixel duplicates in one project reuse the existing image.
3. Choose a model and click **Run prediction**. View overlay, binary mask, or
   probability map; inspect pixel count and image-area coverage. The model uses
   the trained square input resolution, RGB divided by 255, and bilinear image
   resizing. Probabilities are bilinearly mapped to the original dimensions
   before thresholding. Tiled inference is not part of Phase 6.
4. Use brush/erase, brush size, undo/redo, and synchronized zoom/scroll. Brush size
   is in original-image pixels. Optionally initialize from the predicted mask.
   Save a draft, or mark **Fully corrected** after reviewing the entire image.
   Each save creates an immutable correction revision. Undo history is bounded
   by 12 actions and an approximate 64 MiB budget for large images.
5. Rerun prediction after saving a complete correction to calculate Dice/IoU
   against that specific revision. Unlabeled images have no accuracy score.
   These are correction-agreement measurements, not independent research scores.
6. In **Compare versions**, choose another model and run paired comparison. Both
   use the same image, threshold, overlay opacity, and preprocessing. Display
   threshold changes do not change the research benchmark threshold.
7. In **Adapt & review**, assign distinct, fully corrected images to support and
   validation. Choose 1–10 of each; use 1–5 support passes and a recorded seed.
   Images matching known frozen evaluation records are excluded from both roles.
   This detects known exact decoded/file matches, not all re-encoded or near
   duplicate images; users must keep evaluation-image variants out of corrections.
8. Start the CPU job. The encoder is frozen; the decoder and output heads train
   using Adam 0.0001, batch two, BCE+Dice, plus the existing boundary objective
   for a boundary-aware parent. No augmentation or replay is applied. Each step
   saves model, optimizer, sampler cursor/order, configuration, RNG state, and
   correction-manifest identity. Support/validation images and masks are copied
   into an immutable job snapshot so later corrections cannot change a run.
9. Review local validation at threshold 0.50. The fixed gate requires finite
   predictions, exact encoder equality, and at most a 2-point mean Dice drop from
   the parent on the separate user validation images. This is an application
   gate, not the research source-retention gate or evidence of generalization.
   A failed candidate remains available for comparison but cannot be activated.
10. Activate a passing candidate explicitly; previous references/candidates remain
    available for rollback. Finishing a job never changes the active version.
11. Export the project ZIP for originals, masks, overlays, probability arrays,
    measurements CSV, correction revisions, and version/job metadata. Physical
    units are not inferred. Use each job's **Download recovery ZIP** for its
    support/validation snapshot, manifest, config, log, and latest checkpoint.

## Recovery and storage

Default runtime files live under `artifacts/phase6/workspace/` (already ignored by
Git). The synthetic browser test has its own `browser-qa-workspace/`; it does not
populate the user's workspace. Keep a second copy of the entire workspace and
the original verified result ZIPs for full recovery. A project-result ZIP alone
does not contain model weights or all training recovery state.

**Cancel safely** is cooperative: it waits for the current optimizer step and
saves the next recoverable state. Resume a cancelled/failed job from the job card
using the same environment and source code. The checkpoint loader rejects changed
code/configuration/manifest/runtime identities. Older step files are retained.
If a worker exits unexpectedly while the server runs, its job becomes failed.
After a server restart, polling reconciles dead workers after a 30-second startup
grace period and exposes Resume. A running subprocess may finish while the browser
or server is closed; closing the page is not cancellation. Disk failures can still
prevent the newest save; the preceding immutable snapshot is retained.

The service is single-user, bound to 127.0.0.1, with same-origin write protection
and project ownership checks. Do not expose it as a public service. FastAPI's
[file-upload API](https://fastapi.tiangolo.com/tutorial/request-files/) is used
for image and correction uploads. API reference is at `/api/docs`.
